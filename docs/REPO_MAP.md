## AgentScore REPO MAP

### 1. Framework & Runtime
- **Next.js 14.2.0**, App Router only (`src/app/`, no `pages/` dir). React 18.3, TypeScript 5.3 (strict mode: `strict`, `strictNullChecks`, `noImplicitOverride` all on; `noUnusedLocals`/`noImplicitReturns` off).
- `next.config.js`: **`typescript.ignoreBuildErrors: true` and `eslint.ignoreDuringBuilds: true`** — production builds do NOT fail on type/lint errors; `npm run type-check` is the real gate.
- Path aliases: `@/*` → `src/*`, plus `@/components`, `@/app`, `@/lib`, `@/hooks`, `@/types`, `@/utils`.
- Deploy target: **Vercel**, project `agentscore` under team `kryptoremontiers-projects`. GitHub-integrated (auto-deploy per push/branch; `main` → production).
- Windows dev quirk: webpack cache disabled in dev (`config.cache = false`) to avoid HMR file-lock errors; TLS verification disabled in dev only (`NODE_TLS_REJECT_UNAUTHORIZED=0`) for corporate/VPN cert issues.

### 2. API Routes (`src/app/api`)
**`/api/v1`** (Trust API, all wrapped in `apiSuccess`/`apiError`, CORS `*`). Every GET is `export const GET = withReadLedger(handleGET)` (`lib/api-helpers.ts`; a test enforces it) and every answer's `meta` carries **`dataAgeSeconds`** (whole seconds since the oldest indexer read behind it, when the answer was built; `0` = read live) and **`dataReadAt`** (that read's ISO time — absolute, so a CDN `Age` on top can't hide it). An answer built on an incomplete read is sent `Cache-Control: no-store`; a complete one `public, s-maxage=15, stale-while-revalidate=30` (trust route 60/300, card 60). MCP tool answers carry the same `meta` (`lib/mcp-freshness.ts`). No route sets `revalidate` (it was inert: the reads are `no-store`); caching lives in the data layer (§3 "Shared server cache").
- `GET /api/v1` — index of all endpoints
- `GET /api/v1/agents` — list agents w/ scores (sort: score/stakers/newest), served from the cached corpus (60 s). Test-fixture atoms and duplicate re-registrations are filtered out by default (`lib/agent-junk-filter.ts`, §3) and counted in `meta.junkFiltered`; pass `?includeJunk=true` to get all atoms back, each junk one tagged with a `junkReason`. Every row carries **`scoreBasis: 'measured' | 'prior'`** next to the unchanged `score` envelope (also on `/agents/:id`): `'prior'` = the atom holds no stake (support + oppose shares = 0), so `score.trustScore` is the engine's neutral 50 anchor and `agentScore`/`objectScore` rest on it — not a measurement; consumers should render it as "—". Same rule as the UI (`lib/score-basis.ts`, §4).
- `GET /api/v1/agents/:id` — agent detail. The scored AgentScore corpus first (`getAgentDetail`), then the ERC-8004 cohort (`getCohortAgentDetail` ← `lib/cohort-reader.ts` `fetchCohortAgent`, one subject, the cohort list's own identity filter): `origin: 'erc8004'`, identity, declared domains/skills (null = classification unread), attestation tier + attesters + attested domains; no score/stake/staker fields (`scoreBasis: null`). Unknown id → 404; a failed read → 500, never 404. MCP `get_agent_trust` resolves the same way; the `/agents/[id]` page uses the same single-subject lookup.
- `GET /api/v1/agents/:id/trust` — full trust/quality/object score breakdown
- `GET /api/v1/agents/:id/card` — A2A-compatible agent card (detail+trust in parallel)
- `GET /api/v1/agents/:id/timeline` — trust score history. `currentScore` is the measured AGENTSCORE or `null`, with `scoreBasis`: `'measured'`, `'prior'` (no stake, so nothing measured) or `null` (the atom is not a scored AgentScore agent, e.g. an ERC-8004 cohort agent). It is never the 50 anchor or a fallback constant (`lib/score-basis.ts` `publishedAgentScore`). A failed read is a 500, never a 404 "Agent not found" (`fetchTimelineData` returns `null` only when there is no such atom).
- `POST /api/v1/agents/register` — "prepare mode": validates + structures registration payload (no server-side tx signing)
- `GET /api/v1/skills` — list skill atoms w/ aggregate stats
- `GET /api/v1/skills/:id` — skill detail + agents in it
- `GET /api/v1/domains` — canonical domain buckets w/ aggregate stats
- `GET /api/v1/domains/:id/agents` — agents in one domain
- `GET /api/v1/evaluators` — evaluator leaderboard, filter by tier (cached leaderboard, 300 s; a failed read is a 500, never an empty list)
- `GET /api/v1/evaluators/:address` — one evaluator's accuracy/PNL/tier profile. A failed (or capped) attestation read gives `attestationCount` / `meetsAttestationThreshold` / `attestationGateActive: null` with an `attestationMessage` saying so, never 0; above 1.0x the gate decides the weight, so `evaluatorWeight` is `null` then too (`rawEvaluatorWeight` stays). Answer sent `no-store`. MCP `get_evaluator` is the same.
- `GET /api/v1/trust/query` — filtered trust query (skill/minTrust/minStakers)
- `GET /api/v1/leaderboard` — ranked agent leaderboard (the cached corpus, 60 s)
- `GET /api/v1/stats` — platform-wide stats, composed from shared cached reads (corpus and domains 60 s, the counts and the evaluator leaderboard 300 s; `meta.dataAgeSeconds` is the oldest part). `agents` is the post-junk corpus total and equals `/api/v1/agents` `meta.total` whenever both answer from the same corpus read (same `meta.dataReadAt`): both (and MCP `platform_stats`) read the same `loadAgentCorpus()` in `api-data.ts` (fetch → oppose → `rowToAgentItem` → `filterAgents`, cap `AGENT_CORPUS_LIMIT = 500`, truncation from an `atoms_aggregate` on the same filter — `meta.truncated` / `agentsTruncated`). `topAgent` is chosen among measured scores only. `attesters` = distinct wallets with a live position on any attestation triple (`is skilled in` → canonical domain; `summarizeAttesters`). `skills` is an `atoms_aggregate` count: the old row read was capped at 250. `claims` counts the claims AgentScore lists — subject and object both AgentScore agents or skills, the same `where` as the `/claims` page and the landing's Claims tab (`AGENTSCORE_CLAIMS_WHERE_STR` in `lib/gql-filters.ts`); it used to count every triple on the network (78,306 on testnet against 15, Etap 4c). A count whose read failed (`attesters`, `claims`, `skills`, `domains`, `evaluators`) is `null`, never 0. Only the corpus read can fail the whole route, so a failed side read never blanks the agents, stake or stakers numbers. The landing Hero, Stats and CTA read only this route (`lib/landing-stats.ts`): loading and failure print "—" or no number, never 0. The Hero's former "Attestations" (position rows + every triple with an agent subject) is now "Attesters".
- `GET /api/v1/forge/projects` — list IntuForge projects. Duplicate re-registrations of the same project are folded to one representative by default (`lib/agent-junk-filter.ts`, §3), counted in `meta.junkFiltered`; pass `?includeJunk=true` to get the folded duplicates back too.
- `POST /api/v1/forge/projects` — register new IntuForge project
- `GET /api/v1/forge/projects/:id` — project detail
- `GET /api/v1/forge/projects/:id/trust` — project trust score
- `GET /api/v1/forge/stats` — forge-wide aggregate stats
- `GET /api/v1/forge/leaderboard` — forge leaderboard by category (read live)

**Other:**
- `GET/POST /api/mcp` — 307 redirect to `/api/mcp/mcp`
- `GET/POST /api/mcp/[transport]` — MCP server (`mcp-handler`), 9 tools wired here (search/detail/trust/domains/evaluators/query/stats/register/timeline). Agent rows in `search_agents`, `get_agent_trust` (`agent`), `compare_agents`, `trust_query` and `get_domain_ranking` carry the same `scoreBasis` field (domain rows: basis = the domain triple's own stake). `compare_agents` ranks through `lib/agent-compare.ts`. Only measured scores compete: an agent whose score is the prior (or, with `skill`, whose skill triple has no stake, or which lacks the skill) gets `comparedScore: null` with `comparedBasis` `'prior'`/`'missing'`, ranks after every measured agent, and is never the `recommendation` (null when nothing is measured). `get_agent_timeline` follows the REST timeline rule (`currentScore` null + `scoreBasis`).
- `GET /api/feedback` — list feedback entries (admin-token protected)
- `POST /api/feedback` — submit feedback (public)
- `PATCH /api/feedback/:id` — mark resolved (admin-token protected)

### 3. Data Layer
- **No single shared GraphQL client** — the fetch-POST-to-Hasura pattern is reimplemented independently in several files: `api-data.ts` (own `gql<T>()`, server-side, `cache: 'no-store'`), `attestation-reader.ts` and `pnl-engine.ts` (each their own inline `fetch`/`gql`), and `graphql-client.ts` (`graphqlRequest()`, resolves testnet/mainnet URL from `constants.ts` `API.graphql`).
- **Liveness verified (grep, 2026-08-27; dead hooks removed 2026-08-28): `graphql-client.ts` has exactly one live consumer — `domain-data.ts`'s `fetchDomainCategoryGraph`, imported by `src/app/lab/poc/page.tsx`. The three client hooks that previously imported `graphql-client.ts` (`useTrustScore`, `useAgents`, `useAgent`) were confirmed unimported outside their own barrel (`hooks/index.ts`) and deleted; the stale month-old cleanup stash (which also deleted `graphql-client.ts` itself, wrongly) was dropped, not applied.**
- Endpoint: `APP_CONFIG.GRAPHQL_URL` (`app-config.ts`) = `NEXT_PUBLIC_GRAPHQL_URL` ?? `https://testnet.intuition.sh/v1/graphql`.
- Example query (from `pnl-engine.ts`): `GetWalletPositionsWithPNL($wallet: String!, $termIds: [String!]!) { positions(where: {...}) { term_id shares total_deposit_assets_after_total_fees total_redeem_assets_for_receiver vault { current_share_price total_shares total_assets } } }`.
- **Shared server cache** (`lib/server-cache.ts`, Etap 4b-cache): `completeReadCache(key, read, { revalidate, tags })` over `unstable_cache` (the Vercel Data Cache, shared by every function instance). TTLs in `SERVER_CACHE_TTL`: agent corpus 60 s (`loadAgentCorpus` — the list, stats, leaderboard, MCP search, AND the agent detail/trust breakdown, which read the agent from the same snapshot: `agentSnapshot`), domain triples and the skill-atom list 60 s, per-agent skill triples, timeline and a subject's attestations 30 s (tag `agent:<termId>`), the ERC-8004 cohort 300 s (`loadErc8004Cohort` — the ERC-8004 agent detail reads its agent from it, as the AgentScore detail reads the corpus; an id missing from a cohort read to the end is not a cohort agent, one the cohort couldn't answer for falls back to the live single-agent read), stats counts 300 s, evaluator leaderboard 300 s, the `/leaderboard` contributor ranking 300 s (`lib/leaderboard-data.ts`, every read paged; the page renders dynamically and prints the data's age, `lib/data-age.ts`). A read returns `{ value, complete }`; **only complete reads are stored** — a read that threw, stopped at a row cap, or settled a sub-read to `null` is returned as-is and the next caller reads again. Past 2 × TTL a cached value is not served (read live) — **unless that live read fails: then the last complete read is served with its real age** (Etap 4c; no entry and a failed read → the failure). **Each entry's TTL is the configured one ±10 %** (`jitteredTtl`), drawn when the entry is read and stored with it; a call passes the TTL of the entry it last saw under those arguments as `revalidate` (`unstable_cache` judges staleness by the call's `revalidate`, so a fresh draw per call would refill everything at ~0.9 × TTL together). Entries filled together at start-up used to refill together every 300 s. One read in flight per key and arguments on each instance: concurrent misses (and Next's per-request background refills of a stale entry) share it — a slow indexer used to multiply the reads. Each request runs in a read ledger (`runWithReadLedger`), from which `currentFreshness()` gives the answer's age and completeness. **Don't nest cached reads**: Next bypasses `unstable_cache` inside another's callback (it re-reads live) — compose outside, as `getPlatformStats` does. Never wrapped: anything wallet-specific (the user's own position, an evaluator's positions and attestations), IntuForge, and every browser-side read. Outside a Next server (tests, scripts) the cache falls back to reading live.
- **The /agents page reads through the cache** (Etap 4c, `lib/agents-page-data.ts`, contract in `lib/agents-page-types.ts`): two internal routes, not part of the public REST surface. `GET /api/v1/agents/page` — the list in one answer: `agentScore` (the cached corpus as list rows with their vault snapshot, junk/fetched/total/truncation, and the corpus's attestations), `cohort` (the cached ERC-8004 cohort) and `cohortAttestations` (cached per cohort id set, 60 s). `GET /api/v1/agents/page/:id` — one listed agent's modal extras: `vault` (trust triple + raw positions, 30 s), `signals` (30 s), `skillTriples`, `reports` (30 s) and `stakerWeights` (from the cached evaluator leaderboard; 400/404 for a malformed or unlisted id). Every **part** is `{ status: 'ok', value, dataReadAt, dataAgeSeconds, complete, staleAfterSeconds }` or `{ status: 'failed' }` — never an empty list for a failure; a part is stale past 2 × its TTL + the CDN window (`staleAfterSeconds`), which is when the page says "Updated N min ago" instead of "GraphQL live feed". Values go through `lib/json-codec.ts` (bigint, Map). A failed part makes the answer `no-store`.
- **On-chain reads**: `viem` `createPublicClient` against Intuition Testnet RPC (`api-data.ts` server client, `on-chain-pricing.ts` for cached share price, 15s TTL) — used for live share-price reads, not the bulk of data (Hasura indexer is primary source).
- IPFS/Pinata metadata upload is wired as an *optional*, currently-unused path (env var present, no `PINATA_JWT`/`createAtomFromThing` call found in `intuition.ts`).
- **`lib/agent-junk-filter.ts`** — test-fixture + duplicate-registration filter for agents and IntuForge projects (thesis §6: counted and surfaced, never silently dropped). Two mechanisms: (A) blocklist by exact `term_id` (+ regex on label as a second net) for verified-zero-active-stake fixtures; (B) fold duplicate re-registrations of the same real thing to one representative, tie-break `stakerCount` desc → `totalStake` desc → `createdAt` asc — distinct stakers ranked above raw stake deliberately (thesis §4: sybil-safe measure is wallets, not capital). Wired at every fetch path that returns agent/project lists — `api-data.ts`'s `getAgentsWithScores`, `forge/data.ts`'s `fetchForgeProjectsWithJunkInfo`, the `/agents` page's own independent client-side GraphQL fetch (§3's "no single shared GraphQL client" applies here too — filtering has to be applied in each place separately), and the MCP `search_agents` tool; also `getPlatformStats` (via the shared `loadAgentCorpus()`, so `/api/v1/stats` and MCP `platform_stats` count the same rows as `/api/v1/agents`) and the landing `FeaturedAgents` agents tab (whose "N indexed" badge now reads `/api/v1/agents` `meta.total`, not its own `limit: 8`).
- Env vars referenced in `src/`: `NEXT_PUBLIC_GRAPHQL_URL`, `NEXT_PUBLIC_NETWORK`, `NEXT_PUBLIC_CHAIN_ID`, `NEXT_PUBLIC_CHAIN_ENV`, `NEXT_PUBLIC_INTUITION_RPC_URL`, `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_WC_PROJECT_ID`, `NEXT_PUBLIC_AGENT_PREFIX`, `NEXT_PUBLIC_SKILL_PREFIX`, `NEXT_PUBLIC_APP_SCOPE`, `NEXT_PUBLIC_ALPHA_DATE`, `NEXT_PUBLIC_PLATFORM_TAG`, `NEXT_PUBLIC_PLATFORM_FEE_WALLET`, `NEXT_PUBLIC_PLATFORM_REG_FEE`, `NEXT_PUBLIC_PLATFORM_STAKE_FEE_BPS`, `NEXT_PUBLIC_ENABLE_TEST_PAGE`, `FEEDBACK_ADMIN_TOKEN`, `NODE_ENV`.

### 4. Scoring
- **`lib/scoring/types.ts`** — canonical `ScoreEnvelope` returned by all endpoints:
```ts
interface ScoreEnvelope {
  objectType: 'agent'|'claim'|'evaluator'|'project'|'skill'
  trustScore: number          // 0–100
  qualityScore: number | null // 0–100, null on list endpoints
  objectScore: number | null  // trustScore×0.60 + qualityScore×0.40
  tier: TrustLevel
  softGateActive: boolean     // always false (removed)
  computedAt: string          // ISO-8601
}
```
- **`lib/scoring/engine.ts`** → `computeScoreEnvelope(input: ComputeScoreInput): ScoreEnvelope` — thin orchestrator, delegates math.
- **`lib/hybrid-trust.ts`** → `calculateHybridScore(trustScore, compositeScore, supportRatio): number` (60/40 blend, rounded to 0.1) and `getHybridLevel(score): TrustLevel` (80/60/40/20 bands).
- **`lib/score-basis.ts`** → `hasMeasuredScore({ supportWei, opposeWei })`: the ONE rule for whether a trust score may be printed — total stake on the atom (support + oppose shares) > 0 with the support side actually read (`readSharesWei` returns `null` for a never-fetched aggregate, `0n` for a fetched empty one). At zero stake `calculateTrustScoreFromStakes` returns its neutral 50 anchor (confidence 0); that formula is correct and untouched, but the result is a prior, not a measurement. `measuredScore()` → number or `null` ("—" + "No stake yet — nothing to measure."), `qualityBucket()` → level or `'unrated'` (the /agents quality filter never files an unmeasured row under Moderate), `scoreBasisOf()` → the API's `scoreBasis`. Gate on stake, never on staker count: a zero-share position still counts in `positions_aggregate.count`. A stake never read on that surface (`supportWei: null`, the ERC-8004 cohort rows) says "not read on this list", never "No stake yet" (`noScoreTooltip`). A failed oppose read is `opposeWei: null`: unknown, so there is no measured score ("—", `OPPOSE_UNREAD_TOOLTIP`). It is never taken as 0 oppose, which would inflate the score (the /agents list and the landing Featured cards; REST/MCP reads throw instead). Etap 4b-close extends the rule to every surface through the same helpers (`annotateVaultReads` → `stakeReadingOf` → `scoreUnlessOpposeUnread` / `OPPOSE_UNREAD_TOOLTIP`): /skills and /claims cards print "—" with the reason, and their modals show `OpposeUnreadNotice` instead of a score (claims: the on-chain supply read). Evaluator data (`trustRatioOf`) gives `currentTrustScore: null`; `calculateEvaluatorScore` leaves such a pick out of the track record, and REST/MCP `trackRecord` carries `currentTrust`/`correct: null`. IntuForge (`forgeOpposeWei`) gives `trustScore`/`compositeScore`/`finalScore`/`opposeStaked: null` and `score: null`; such a project ranks last (`compareForgeScoreDesc`) and is left out of the average (`meanKnownForgeScore`, null when none is known).
- **`lib/composite-trust.ts`** → `calculateCompositeTrust(input: CompositeTrustInput): CompositeResult` — 4-pillar composite (signal 40%, staker diversity 25% log2-scaled, stability 25%, price retention 10%); also whale-exit helpers (`getMaxDailySell`, `getLoyaltyMultiplier`).
- **`lib/evaluator-score.ts`** → `calculateEvaluatorScore(address, positions, options): EvaluatorProfile` — accuracy-weighted evaluator tiering (0.5x–1.5x), consumes `PositionPNL`/`WalletPNL` from pnl-engine when present, falls back to raw trust-score good-pick logic otherwise. Tiers: newcomer/scout/analyst/oracle/sage.
- **`lib/pnl-engine.ts`** (pure + I/O split):
  - `computePositionPNL(raw): PositionPNL` — pure, wei→float via `Number(x)/1e18`, `pnlPercent = totalPNL/costBasis × 100`
  - `calculateWalletPNL(positions: PositionPNL[]): WalletPNL` — pure aggregate (win rate, total PNL)
  - `isProfitablePick(position): boolean`
  - `fetchPositionPNL(wallet, termIds): Promise<PositionPNL[]>` — async GraphQL fetch, degrades to `[]` on error (never throws)
  - `PositionPNL = { termId, shares, currentSharePrice, currentValue, costBasis, realizedValue, unrealizedPNL, realizedPNL, totalPNL, pnlPercent, isProfit }`
  - `WalletPNL = { totalUnrealized, totalRealized, totalPNL, totalCostBasis, pnlPercent, positions: PositionPNL[], profitablePositions, totalPositions, winRate }`
  - Consumed by `evaluator-data.ts` and `evaluator-score.ts` only; feeds "good pick" determination and best/worst-pick ranking in the evaluator pipeline. Does not touch `trustScore`/`qualityScore`/`objectScore` directly.

### 5. Auth & Admin
- **Wallet-gated pages**: `src/app/admin/layout.tsx` wraps all `/admin/*` routes (`feedback`, `predicates`) in `<AdminGuard>` (`src/components/auth/AdminGuard.tsx`) — client component, checks `wagmi.useAccount()` against `isAdminWallet()` in `lib/constants.ts` (single hardcoded `ADMIN_WALLET` address, case-insensitive compare). No SSR protection — client-side only, renders "Access Denied" if not connected as that wallet. Sidebar also conditionally shows the admin nav item via the same check.
- **Token-gated API**: `/api/feedback` GET and `/api/feedback/:id` PATCH call `requireFeedbackAdmin(req)` (`lib/feedback-store.ts`), checked against `FEEDBACK_ADMIN_TOKEN` env var — independent of the wallet mechanism above. `POST /api/feedback` is public (no auth) — anyone can submit feedback.
- **All other API routes are public**, no auth — read-only Trust API + MCP surface, rate-limiting/access control not implemented at this layer.

### 6. Conventions
- **Naming**: kebab-case for lib files (`evaluator-score.ts`, `pnl-engine.ts`, `skill-domain-map.ts`); PascalCase for components/pages; camelCase functions/vars.
- **Error handling**: API routes wrap logic in `try/catch`, log `console.error('[API] /x error:', error)`, return via `apiError(message, status)` / `apiSuccess(data, meta)` (`lib/api-helpers.ts`) — consistent `{success, data|error, meta}` envelope, CORS headers on every response. Data-layer async fetches (attestation-reader, pnl-engine) instead **degrade gracefully to `[]`/`null`** on error with `console.warn`, never throw — callers never see a rejected promise.
- **Shared libs**: `src/lib/` (business logic, scoring, data fetching — no React), `src/components/` (UI), `src/hooks/` (client-side hooks; only remaining hook is `useIntuition.ts`, wrapping `@0xintuition/sdk` + wagmi for reads/writes — the three GraphQL-client hooks were removed 2026-08-28 as dead code, see §3).
- **Display formatting** (`lib/format.ts`, added Etap 4a hygiene pass): `formatTTrust(value, opts)` and `formatDate`/`formatDateShort` are the ONE shared formatter for tTRUST amounts and dates — repo rules, both enforced by grep before a hygiene commit ships: no `toLocaleDateString` anywhere in `src` (use `formatDate`/`formatDateShort` instead — they're `Intl.DateTimeFormat`-based, en-US, UTC, so they render identically on every OS locale), and no `$` prefix on a tTRUST amount (tTRUST is not a dollar-pegged asset — `formatTTrust` never emits one).
- **Decimal amount inputs** (`components/ui/DecimalInput.tsx` + `lib/decimal-input.ts`, added Etap 4a): replaces native `<input type="number">` for any tTRUST/share amount field — the native input renders its value using the OS locale's decimal glyph (e.g. "0,05"), which silently breaks parsing on non-US locales. `DecimalInput` is `type="text" inputMode="decimal"`; the comma-to-period normalization, keystroke validation, and max-clamping logic lives in `decimal-input.ts` as plain functions, tested directly in `.test.ts` (the repo has no jsdom/`@testing-library/react` — see below — so the component itself is an untested thin wrapper).
- **No native browser dialogs** (Etap 5a): no `alert()` / `confirm()` / `prompt()` anywhere in `src` (a test greps for them). A failure or warning in a flow is an in-app notice — `useNotice().notify({ kind, text, link? })` (`components/shared/NoticeProvider.tsx`, pure mapping in `lib/user-notice.ts`; `txFailureNotice(action, err)` turns a wallet error into one: a rejection is info, a missing balance links to the Hub). Anything that needs a wallet opens **the** wallet-connect modal — `useConnectModal().openConnectModal({ reason, onConnected })` (`components/wallet/ConnectModal.tsx`, the navbar's button opens the same one) — and `onConnected` carries on where the person was. **The attest path** (`lib/attest-gate.ts`, a pure state machine over the wallet: disconnected → wrong-network → checking-balance → no-balance → ready, one action per step): Attest while disconnected → connect modal → that agent's attest flow; another network → "Switch to Intuition Testnet" (`ATTEST_CHAIN_ID` = the SDK's `intuitionTestnet.id`, one definition, re-exported by `attest-service.ts`); 0 tTRUST → "You need a little testnet tTRUST to vouch — it's free." + the Hub link, re-reading the balance every 8 s so the step moves on by itself; a balance not read yet is "checking", never 0. Intuition's own URLs live once in `lib/intuition-links.ts` (`INTUITION_HUB_URL` — the landing banner, footer, docs and the attest path all use it; a test holds it to one copy).
- **One way to vouch, and backing isn't trust** (Etap 5a): each agent page (modal, profile) holds exactly **one** attest CTA in the DOM — inline in the Attested section on desktop (`AttestedDomains` → `AttestButton variant="inline"`, or the empty state's hero), the `AttestStickyBar` on a phone — chosen with `useMediaQuery(DESKTOP_QUERY)` (`hooks/useMediaQuery.ts`), never CSS-hidden twins; the harness counts `[data-testid="attest-cta"]` on every modal and profile shot. Backing (a stake on the atom vault) is the collapsed `BackThisAgentSection` (`components/profile/`, copy `BACKING_IS_NOT_ATTESTING`) on both surfaces: the modal puts its Buy/Sell panel inside; the profile's "Back with tTRUST" opens that panel (`/agents?open=<id>&back=1`). The profile's former gold "Trust Agent" / "Report Issue" (`TrustButton`) never transacted — a 2 s timeout — and is deleted. No "Bonding Curve Economics … your shares increase in value" copy anywhere (it was on the agent, skill and claim modals).
- **The profile tells the modal's story** (Etap 5a): `/agents/[id]` and the `/agents` modal render the same header — `AtomIdLine` (shortened hex `0x82d87d9517b6...24802c5a`, copies the full id; the profile used to print `BigInt(term_id)` as a 78-digit decimal) and `ProfileStatRow` (attesters · domains attested · tTRUST attested · reports, then the demoted "Backers: N · X on atom vault · N signals" line) from one derivation, `lib/agent-profile.ts` `statRowView` + `backersFromPositions`, over the same parts: the agent's attestations and the modal's cached answer (`/api/v1/agents/page/:id` — vault positions, signals, reports; the profile fetches it too). The harness compares the rendered rows, profile vs modal, for Dackie, Luda and OPEN CLAW (`statRowMatchesModal`). ### 7. Data Integrity

Rules distilled from the Etap 4a / `feat/cohort-limits` work, each tied to the commit that made it necessary — read these before writing anything that fetches, filters, or configures a network.

**Known constraint — the endpoint caps rows per query.** Intuition's Hasura (`testnet.intuition.sh`, verified 2026-09-26) returns at most **250 rows for `atoms` / `triples` / `signals`** and **100 rows for `positions`** per request, whatever `limit` asks for — `limit: 500` gets 250 back and nothing says so. It also rate-limits — **75 requests per minute per client, fixed window** (`ratelimit-limit: 75`, `ratelimit-reset` = seconds to the window) — with a bare **HTTP 429** `{"message":"API rate limit exceeded"}` (no `errors`, no `data`). Paging and per-row reads both spend that budget: batch by id chunks, never per row. Both used to fail silently: `/agents` showed 249 of 263 ERC-8004 agents with `truncated: false`, one classification chunk kept 250 of 449 `has tag` edges, and a 429 made `/api/v1/agents/:id` answer 404 "Agent not found".

1. **Capped fetches report their own truncation, and page past the endpoint's cap.** Any read that can exceed the endpoint's cap goes through `lib/gql-pager.ts`'s `fetchAllRows` (`$limit`/`$offset` over an order ending on a unique key — `term_id` for atoms/triples, `id` for positions), which returns `{ rows, total, truncated }`. It stops only on reaching the aggregate `total` on the SAME `where`, or on an empty page — **a short page is not proof of completion** (that is exactly how the endpoint's cap looks). Our own caps (`COHORT_FETCH_LIMIT = 500`, `AGENT_LIST_LIMIT = 50`, `AGENT_CORPUS_LIMIT = 500`) are the pager's ceiling and stay reported as truncation; the UI surfaces `"showing first N of {total}"` whenever `truncated` is true. Never silently drop (thesis §6). A page failing mid-way throws — never a partial list presented as complete. Positions on agent surfaces are read through `lib/vault-positions.ts`'s `fetchVaultPositions` (the same pager, one place). The pager sends the first page and its count as ONE GraphQL document (`mergeCountIntoQuery`), so a read that fits one page costs one request (Etap 4b-cache: a modal poll tick cost two); a GraphQL-level failure of the merged document falls back to two requests, an HTTP failure (429) does not. The transport (`gqlRequest`, same file) throws on a non-2xx response (after two short retries on 429), on GraphQL `errors`, and on a body without `data`. Reference: `lib/cohort-reader.ts`'s `fetchCohortAgents()` — the identity rows paged to the triple count, `total` from a distinct-subject aggregate on the identical `where`, surfaced in `/agents`'s header. **`total` must be in the same unit as the rows**: the cohort count is `count(columns: [subject_id], distinct: true)` (agents, not same-as triples — an agent with two identity links is one row). Read completely, the deduped row count IS the total; only when our cap stops the read does the aggregate decide, and if it failed there `total`/`truncated` are `null` (unknown) — never a substituted `rows.length`. Same pattern: `lib/agent-list.ts` `fetchAgentListCorpus()`, `api-data.ts` `loadAgentCorpus()`. The `/agents` header prints corpus totals only (never search-dependent); the results line prints the filtered count.

2. **No second source of truth for protocol constants.** Chain ids, registry addresses, and predicate term ids come from `@0xintuition/protocol`, not from a hand-maintained constant in this repo — `src/lib/constants.ts`'s `CHAIN.testnet.id = 0` ("Fill with actual chain ID") is the cautionary example of what happens when one drifts out of sync and is never noticed because nothing reads it. If the SDK lacks a value, wrap the SDK value — don't copy it into a new constant. Reference: `app-config.ts`'s `assertNetworkCoherence()` reads `intuitionTestnet.id`/`intuitionMainnet.id` directly from `@0xintuition/protocol`. (84e3eac.)

3. **Config values that look like they control behaviour must control it, or fail loudly.** Any env var whose name implies an effect (`NEXT_PUBLIC_NETWORK`) is asserted for coherence with the vars that actually drive behaviour (`NEXT_PUBLIC_GRAPHQL_URL`, `NEXT_PUBLIC_CHAIN_ID`) at import time, throwing at boot on a mismatch — a display label that silently stops matching what's actually queried is worse than no label at all. Reference: `app-config.ts`'s `assertNetworkCoherence()`, called unconditionally at module load. (84e3eac.)

4. **Filter/fold/normalize logic lives in one module, and every fetch path passes RAW input to it.** No pre-cleaning at a call site — the two-surface pattern (§3) means two call sites reading the same data independently, and pre-cleaning at only one of them is exactly how they drift apart. Reference: `lib/agent-junk-filter.ts`'s `normalizeAgentLabel()` is the only place a label gets cleaned for fold-matching; both `api-data.ts` and `agents/page.tsx` pass the raw label straight through. (58de434 fixed exactly this — the `/agents` page's own fold had started from a pre-cleaned display name instead of the raw label and silently stopped matching a real duplicate.) Same rule for what `/agents` prints (`lib/agent-list.ts`, 4b-finish): the header line and the origin tabs print one `corpusTotals`; the grid card and the list row print one `attesterLineOf` / `tierChipOf`; the quality dropdown comes from `qualityOptions` (every bucket listed, an empty one disabled with its 0); the origin and quality filters live in the URL (`parseListFilters` / `listFiltersSearch`: `?origin=erc8004&quality=unrated`).

5. **Never fetched is not zero; failed is not empty.** A field the page never read renders nothing (or "—"), not `undefined ?? 0`; a read that failed renders as unavailable, not as an empty result. Reference: `lib/cohort-reader.ts` returns `status: 'error'` (agents `[]`, total `null`) on any failure — distinct from an empty cohort (`status: 'ok'`, total `0`); the `/agents` header prints "ERC-8004 feed unavailable" / "AgentScore feed unavailable" and claims "GraphQL live feed" only when both reads succeeded; cohort cards (which never fetch the atom vault) print no Stakes/Stakers. Same family as `lib/score-basis.ts` (a prior is not a measurement, §4). (Etap 4b-list.) A classification chunk that fails gives its agents `declaredDomains`/`declaredSkills: null` (unknown), never `[]`; `DeclaredDomains` then says it couldn't read them. The /agents attester line (`lib/agent-list.ts` `attesterLineOf`, one helper for the grid card and the list row) makes no claim when the attestation read failed (Attest CTA only), says "No attestations yet" only when the read succeeded, and prints no text while the read is in flight — a fixed-height skeleton holds its line, and a card's shape (compact for rows whose vault the list never read) is decided at first paint, so the answer never moves the layout. (Etap 4b-tier; 4b-finish.)

6. **Caching is fine; hiding the age of cached data is not. A failed read is never cached.** Every cached answer on a machine-read surface says how old it is (`meta.dataAgeSeconds` / `dataReadAt`), and only complete reads are stored (`lib/server-cache.ts`, §3). The evaluator leaderboard's old `unstable_cache` stored a failure as `[]` ("no evaluators") for five minutes, and the attestation gate stored a failed count as 0 attestations; neither does now. A route-level setting that looks like it caches must cache (rule 3) — the old `revalidate` exports on the API routes did nothing and are gone. (Etap 4b-cache.)

**`/agents` reads through our cache (Etap 4c).** For anyone not transacting, the page makes **no** indexer request from the browser: the list (rows, header totals, origin tabs, quality counts, attester lines) comes from `GET /api/v1/agents/page` and the modal (vault/backers, signals, skill triples, reports, staker weights; its attestation view, tier chip and Backers line use the list's data) from `GET /api/v1/agents/page/:id`, refreshed every 15 s while visible (`lib/agents-page-client.ts`). When the indexer is down the page shows the last complete read and the header says "Updated N min ago" instead of "GraphQL live feed" (so does the modal, under its Backers line — on a phone it covers the header; `modalFreshnessLabel`). The list is read once per visit, as before: a tab left open past that bound says how old its list is, too; only with nothing cached at all does it say "Can’t reach the Intuition network right now. Try again in a minute." (`FEED_UNREACHABLE`). **Stays live, straight from the browser** — a user always sees the effect of their own action at once: the connected wallet's own position, the Back/Sell panel (on-chain previews and supply are RPC reads, never the indexer), the refresh right after the user's own trade or report (that agent's positions — its list row follows them, `withLiveVault` — signals, reports and the wallet's position, read live for `OWN_TX_LIVE_MS` = 5 min, longer than the cached answers can lag), and the attest flow. Measured (cold `/agents` + 3 modals within a minute, production builds, `tests/e2e/.local` budget spec): 32 → 0 requests.

**Client budget (Etap 4b-cache; superseded on /agents by Etap 4c above).** The browser reads Hasura directly, against each user's 75/min per IP. The `/agents` modal opens on what the list already read — the trust triple (`as_subject_triples { term_id counter_term_id }`), the vault positions with meta and the oppose sum (`lib/agent-list.ts` `listTrustTriple` / `listVaultSnapshot` / `listOpposeWei`) and the attestation map — and reads only what the list never fetched (signals, skill triples, reports, evaluator weights). Its first poll tick comes when the list's snapshot is one interval old. The modal polls on /agents, /skills and /claims run through `lib/visible-poll.ts` `startVisiblePoll`: no tick while `document.hidden`; back in view, one immediate refresh. Measured (production build): cold `/agents` + 3 modals within a minute 69 → 32 requests; a modal left open in a hidden tab 8/min → 0.
